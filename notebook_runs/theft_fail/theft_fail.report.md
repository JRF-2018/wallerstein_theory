# Extension レポート: theft_fail.matcha

対象: Elecode「Matchaとは」の例（公園のベンチの財布を嫌がらせ目的で持ち去った甲について、窃盗罪の成否を論じたもの）。結論は「甲に窃盗罪は成立しない」。

生成物（同じディレクトリ）:

- `theft_fail.mext`: 本体
- `theft_fail.lean`: 各 Extension が Γ(E)=E を満たすことの Lean 証明
- `theft_fail.alt-reject_v6.mext`: 試算。嫌がらせ目的の評価を争い切った場合
- `theft_fail.alt-use_intent.mext`: 試算。利用処分意思を基礎づける事実が立証された場合

`[ai]` に reject がないので、書かれたとおりの理論（`theft_fail.asis.mext`）は本体と**同一**になる。そのため作っていない。

## 1. 構文チェック

（matcha_check.py の出力）

```
== theft_fail.matcha: エラー 0 件, 警告 0 件
```

エラーも警告もない。木構造の表示では、`!#窃盗罪` の AND のもとに 4 つの要件（他人の財物・窃取・故意・論点「不法領得の意思」）がある。不法領得の意思は `!` で、その下に `+` 排除意思と `!` 利用処分意思が並ぶ。原文の構造どおりに読めている。

## 2. AI の判断（[ai] / [extra]）

### same / neg / failure / effect

**いずれも不要**と判断した。

- 主張は一つだけで、同じ要件を別の主張で繰り返している箇所はない。`[marks]` にも原子の不一致はない。
- 結論「甲に窃盗罪は成立しない」には、主張に `!` の印がある。既定の読みは「不成立からの帰結」（`L2.不成立`）で、原文の意図と合っている。
- 文言の上で否定になっている組（例:「成立しない」と主張 #窃盗罪）は、変換規則がすでに `L2.不成立: ⊤ : -k1, c1 / c1` として結んでいる。改めて `neg` を書く必要はない。

### review（あてはめの審査）

| 対象 | 判定 | 理由（要約） |
|---|---|---|
| A@占有者 | **doubtful** | 要件は「占有者の**意思に反して**」である。A を占有者に当てることは L6-7 の認定で支えられるが、A が同意していないという事実が書かれておらず、一段飛んでいる |
| （L7 の事実群）@Aが財布を実力的に支配している | ok | ベンチに置いたまま短時間・近距離離れた者の占有を認めるのは判例の通常の評価（置き忘れ事案。最決平成16年8月25日刑集58巻6号515頁など）。限界は事案ごとに争われうる |
| 甲@自己 | ok | 持ち去ったのは甲自身 |
| 持ち去った@移転 | ok | 持ち去りは占有の移転そのもの |
| 持ち去った@権利者Aを排除して | ok | 持ち去れば権利者は物を使えない |
| いやがらせをする目的だった@財布そのものから効用を得るわけではない | ok | 毀棄・隠匿の目的で利用処分意思を否定するのが判例・通説（大判大正4年5月21日刑録21輯663頁）。嫌がらせ目的もこの類型に入る |

（判例の引用は、AI がこの評価の一般的な根拠として挙げた参考である。原典には書かれていない。）

### [extra]

本体では**追加していない**。足さなくても論証は形式的に成り立ち、著者の根拠（嫌がらせ目的）は結論に直接つながっている。

### 保留した判断

- 「甲は前記事実を認識認容している」（故意）は、評価なしの当然のあてはめとして変換されている。「前記事実」が何を指すかは文中で特定されていないが、審査対象にするほどの飛躍ではない。review は付けていない。
- 論点 `? 財産犯と不可罰的な使用窃盗及び遺棄・隠匿罪との区別する必要がある` は理由（`~>`）を持たない。そのため、変換規則により q1 ↔ 不法領得の意思 となる。論点の文言を独立の命題として扱うかどうかは判断を保留し、変換の既定に従った。

## 6. あてはめの実質的妥当性

- **review の結果**: 6 件のうち 5 件が ok、1 件（A@占有者）が doubtful、reject はない。そのため書かれたとおりの理論は本体と同一である。
- **構造の問題（A@占有者）**: 窃取の要件「占有者の意思に反して」に対して、原文のあてはめは「A@占有者」だけである。「A が占有者である」ことは L6-7 の占有の認定と重なっていて、「意思に反して」（被害者の不同意）を支える事実はない。通常の事案では不同意は推認されるので、結論には影響しにくい。ただ、形式化すると「占有者が誰か」と「その意思に反するか」が一つの評価に畳み込まれていることが見える。書き直すなら、`+%占有者の意思に反して <= Aは持ち去りに同意していない` のように、不同意の事実を独立に書くのがよい。
- **事実の食い違い**: なし。「持ち去った」は L9 と L13 で同じ原子 f7 として共有されていて、整合している。
- **誤記の疑い**: なし。論点の文言「…との区別する必要がある」は助詞が不自然（「…とを区別する」の意か）だが、論理には影響しない。
- **試算（reject の場合）**: `theft_fail.alt-reject_v6.mext` で、嫌がらせ目的の評価 e6 を除いた（争い切った）場合を計算した（mext.py の出力: Extension 1 個、preferred 1 個。生成デフォルト = e1, e2, e3, e4, e5, L2.不成立）。
  - 利用処分意思は肯定も否定もされない（r13・-r13 のどちらも E に含まれない）。そのため k1・-k1 のどちらも E に含まれない。
  - それでも `L2.不成立` の正当化 -k1 は無矛盾なので、**c1「窃盗罪は成立しない」は依然として導かれる**。著者の `!` の印もすべて「一致」のままである。
  - （解釈）この変換では、「成立しない」は「成立が立証されていない」でも導かれる。刑事では検察官が不法領得の意思を立証する責任を負うので、この読みは立証責任の分配と合っている。

## 8. 反論の候補（立証責任）

1. **利用処分意思を基礎づける事実の立証**（検察側）
   - 試算 `theft_fail.alt-use_intent.mext`。`[extra]` に次の 2 つを足した。
     - 事実「財布の中の現金を使うつもりもあった」
     - 規則「→ 利用処分意思」
   - （mext.py の出力）Extension 1 個（preferred 1 個）。生成デフォルト = e1, e2, e3, e4, e5, L2 で、E1 に k1（窃盗罪成立）が入り、c1 は入らない。衝突しうるデフォルトは e6, L2, L2.不成立 である。
   - 印 `!` の L14・L12・L2 は「不一致」になる。
   - 利用処分意思が肯定されると、e6 の正当化 -r13 が崩れ、嫌がらせ目的の評価は働かなくなる。主たる目的が嫌がらせでも、副次的な利用の意思で足りるかどうかは、実務・学説上の争点になりうる。
2. **嫌がらせ目的の評価を争う**（検察側）: §6 の試算のとおり、争い切っても「立証なし」にとどまり、結論は変わらない。結論を覆すには、上の 1 の積極的な立証が要る。
3. **占有の否定**（弁護側の予備的主張。ただし本件では結論が同じなので実益は小さい）: 「20 m・5 分」で A の占有はすでに失われていたと争えば、遺失物等横領罪（刑法 254 条）の問題に移る。ただし同罪も不法領得の意思を要するので、本件の結論は変わらないと見込まれる（試算はしていない）。
4. **論証の外側**: 窃盗罪が否定されても、財布を隠したり捨てたりしていれば器物損壊罪（刑法 261 条。隠匿を含む）が問題になりうる。原文の論点の文言（「遺棄・隠匿罪との区別」）もそれを示唆するが、本 Matcha ファイルは窃盗罪だけを扱っている。

## 10. 結論

**(a) 形式的妥当性**: 成り立つ。主張された結論「甲に窃盗罪は成立しない」は、唯一の（preferred）Extension E1 に含まれ、懐疑的帰結でもある。著者の成否の印 10 個はすべて mext.py の結果と一致し、Lean による Γ(E1)=E1 の検査も通った。

**(b) 実質的妥当性**: おおむね説得的である。結論は「嫌がらせ目的 → 利用処分意思の否定 → 不法領得の意思の否定」という判例・通説に沿った一本の鎖で支えられ、その要のあてはめ（e6）は ok と判断した。弱い点は次の 2 つである。

- 「占有者の意思に反して」のあてはめが「A@占有者」だけで、被害者の不同意を示す事実がない（doubtful。結論への影響は小さい）。
- 甲に財布の中身を利用する意思が少しでもあれば結論が逆転する（§8 の試算）。そのため、嫌がらせ「だけ」が目的だったという事実認定が論証の実質を担っている。

## 道具について

- `explain` の出力は、深さの上限で途中が「…」になる（-r13 の先）。その先は `explain E1 "¬窃盗罪／%経済的用法に従って利用処分する意思"` を別に実行して補った（§4）。不具合ではないが、上限を引数で変えられると便利である。
