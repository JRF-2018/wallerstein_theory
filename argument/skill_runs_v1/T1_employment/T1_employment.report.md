# Extension レポート: T1_employment（employment_core.matcha + employment_periphery.matcha + employment_unknown.matcha）

対象は、`argument/build_argument.py` がシミュレーションの出力（`sims/out/sim1.json`、`sim2.json`）から生成した 3 つの Matcha-D ファイルである。3 ファイルで一つの理論 `T1_employment.mext` をなす。

- **中核**（employment_core）: 雇用安定の原則があてはまり、周辺例外の主張は `!`（不成立）と印が付いている。
- **周辺**（employment_periphery）: 周辺例外の主張が `+`（成立）で、`!> $雇用安定_周辺` によって原則を退ける。
- **地域U**（employment_unknown）: 地域の位置も外資の撤退ハザードも分からない。例外の要件は書かれているが、それを支える事実がない。

以下、「（mext.py の出力）」「（matcha_check.py の出力）」と書いた部分はプログラムの出力をそのまま貼ったものである。それ以外は AI（Claude）の判断と解釈である。

コマンドは `python3 tools/matcha_check.py --shared-labels --tree employment_core.matcha employment_periphery.matcha employment_unknown.matcha`。

（matcha_check.py の出力・先頭行）


エラーも警告もない。構文木も原文の構造（原則の主張 → 例外の主張 `!> $原則`）どおりに読めている。

## 2. AI の判断（[ai] / [extra]）

### 2.1 same / neg / failure / effect

**どれも書いていない**。理由は次のとおり。

| 種類 | 判断 | 理由 |
|---|---|---|
| same | 不要 | 要件「業務が恒常的」は主張ごとに別の原子（`雇用安定_中核／…` など）になる。しかし、どれも同じ事実から直接導かれ、ほかの主張で根拠なく繰り返されてもいない。[marks] に、同一視の漏れによる不一致はない |
| neg | 不要 | 周辺と地域U の例外の結論は `>> not 期間の定めのない雇用とすべきである` と明示されており、すでに `-c3`・`-c4` になっている |
| failure / effect | 不要 | 中核の周辺例外は `!` なので、「中核では周辺例外は認められない」は「不成立からの帰結」と読む。周辺は `+` なので「効果」と読む。地域U は印がなく下位にも `!` がないので「効果」と読む。どれも既定の読みが正しい |

### 2.2 あてはめの審査（review）

§6 に表を載せる。`ok` が 6 件、`doubtful` が 1 件、`reject` は 0 件である。

### 2.3 背景知識 [extra]

**本体には何も足していない**。形式的には背景知識なしで論証が閉じる。根拠が結論につながっていない箇所もない（ただし、「事実上の規範」から当為を導く点に実質的な問題がある。§6.3 で述べる）。

§6・§8 の試算では、写し（`T1_employment.alt-*.mext`）の [extra] / [ai] だけを変えている。

### 2.4 保留した判断

- 事実「需要の変動にさらされない職である」は、3 つのファイルで同じ文言なので、変換規則により一つの事実原子 `f2` にまとまる（§6.4）。意味としては地域ごとの別の事実だが、W にある確定事実なので、今の理論では結果に影響しない。そのため same や分割はしていない。

### 6.3 構造の問題（AI）

1. **「事実上の規範」から当為を導いている**
   - 周辺例外は、根拠を「世界システム上の位置（事実上の規範）」と明記した主張である。結論は「期間の定めのない雇用とすべきで**ない**」という当為になっている。
   - シミュレーションが示すのは「外資の退出オプションがあると、企業は非正規を選ぶ割合が増える」という**事実の傾向**である。そこから「すべきでない」は出てこない。
   - 形式的には `!>` によって例外が原則（労働者派遣法 25 条・労働契約法 18 条の趣旨）に優先する。しかし、事実上の規範が実定法の趣旨に優先すべきだという根拠は、理論のどこにも書かれていない。
   - この理論は「実際に働いている規範の記述」として読むのが正確だと考える。その場合は、結論を「期間の定めのない雇用とされない（事実上）」のように記述的に書くほうがよい。当為として読むなら、優先の根拠を `:: 優先` か [extra] で明示する必要がある。T4（法による介入）の理論は、この優先を争う位置にある。
2. **割合から全称の結論を出している**
   - 周辺の非正規の割合は 0.513 なので、「周辺の安定した職」一般について「期間の定めのない雇用とすべきでない」とまでは言えない。
   - 例外の結論は「周辺の安定した職の相当部分で」と限定するのが、シミュレーションに忠実である。
3. **「周辺」の代理指標**
   - 工業能力のシェア（Sim 1）は中核／周辺の代理指標として妥当である。ただし、世界システム論の周辺性は、価値移転や不等価交換という関係で定義される。
   - Sim 2 の `transfer` や `status_rent_to_core` を根拠に加えると、Wallerstein の概念により近いあてはめになる。

### 6.4 事実の食い違い・誤記の疑い

- 誤記は見つからなかった。著者の印と preferred の Extension はすべて一致する。
- 事実「需要の変動にさらされない職である」は、3 地域で同じ文言なので一つの原子 `f2` にまとまっている（§2.4）。今は確定事実なので害はない。しかし、たとえば「周辺の職は外資撤退の変動にさらされる」という反対事実を一地域についてだけ足すと、3 地域すべての原則が崩れる。
  - 生成スクリプト（build_argument.py）で「需要の変動にさらされない職である（周辺）」のように地域を文言に含めることを勧める。
- 周辺の職を「需要の変動にさらされない」としながら、同じ職の外資は年 25% で撤退しうる。これは論理的な矛盾ではない（業務の恒常性と資本の移動性は別の変数である）。しかし、「業務が恒常的」の評価を争う反論の足がかりになりうる（§8）。

**反論の筋（AI）**:

- **原則の側（労働者の側）**:
  - (a) 外資の退出オプションの評価を争う（alt-v4-reject）。たとえば、撤退ハザードは個々の雇用主の意思ではなく市場全体の性質である、と主張する。

  - 地域U では、位置と退出オプションの**両方**を立証しなければならない（alt-U-proven と alt-U-position-only の対比）。
  - 情報がないときに原則が残る（地域U の本体の結論）ことは、デフォルト論理での「立証責任は例外を主張する側にある」をそのまま表している。

  - 二つの評価（シェア 0.974、ハザード 0.05）を**両方**覆す必要がある。§4 の explain の［根拠 1/2］［根拠 2/2］が示すように、`-x1` には独立した二つの根拠があるからである。

## 9. 予測した Extension の検証

**経緯（正直な注記）**: このスキルを起動した時点で、`T1_employment.mext` にはすでに以前の `solve` の結果（`[extensions]` の E1・E2 と `[summary]`）が書かれていた。そのため、以下の予測は Extension を見ないで立てたものではない。

予測の中身は、原文の構造（原則 → `!>` の例外、地域U は事実なし）から直接読めるとおりのものである。AI の判断（review）はいずれも結論を変えない（reject がない）。

```
P1*: c1, -k2, c2, k4, -c3, c4, !k6    ; 中核は原則、周辺は例外が優先して勝つ、地域Uは例外の要件が立証されないので原則
P2:  c3, !k4, c1                      ; 優先を無視すれば、周辺でも原則が先に働いて例外の正当化を潰す Extension がある
```

（MEXT ファイルでは、上の名前の代わりに原子の文言で書いている。）

（mext.py の出力: `mext.py verify`）

```
P1: OK（主張されたリテラルを満たすpreferred Extension: E2）
P2: OK（主張されたリテラルを満たすExtension: E1）
```

（mext.py の出力: `mext.py verify --skeptical`）

```
P1: OK（すべてのpreferred Extensionで成り立つ: E2）
P2: NG（成り立たないExtensionがある。成り立つのは E1）
```

- P1 は、信憑的にも懐疑的にも当たった。
- P2 は、信憑的には当たった（E1 がそれである）。懐疑的には NG で、これは**予測どおり**である。P2 は「preferred でない Extension が存在する」という予測なので、すべての Extension で成り立つとは主張していない。
- 文言が解決できずに書き直したことはない。

## 10. 結論

**(a) 形式的妥当性**:

- 著者が主張した結論は、すべて唯一の preferred Extension E2 に含まれる（懐疑的帰結）。結論は次の三つである。
  - 中核: 期間の定めのない雇用とすべきである。周辺例外は認められない。
  - 周辺: 例外が成立し、期間の定めのない雇用とすべきでない。
  - 地域U: 例外が立証されないので原則が残る。
- 著者の印もすべて E2 と一致する。E2 が Extension であることは Lean で確認した。
- 優先順位を無視した E1 では周辺の結論が逆になる。ただし、`!>` の優先によって E1 は退けられる。

**(b) 実質的妥当性**:

- あてはめは概ねシミュレーションの数値で支えられている（ok 6 件）。
- ただし、周辺の「外資の退出オプション」の評価文言（「いつでも引き上げられる」）は誇張である（doubtful）。この一点を退ければ、周辺でも原則に戻る（alt-v4-reject）。周辺の結論は、この評価に全面的に依存している。
- より根本的な問題は、例外の根拠が「事実上の規範」であるにもかかわらず、実定法の趣旨に優先し、しかも当為（「すべきでない」）として結論している点である（§6.3）。
- シミュレーションが支えるのは、「周辺では、外資の退出オプションのために、安定した職の約半分が非正規になる」という**記述**である。
- 以上から、この理論は「周辺で実際に働いている規範の再構成」として読む限り説得的だと考える。規範的な主張としては、優先の根拠が欠けている。
- 地域U の扱い（情報がなければ原則）は、立証責任の配分として妥当である。

## 道具について

- **事実の文言の共有**: 文言が同じ事実は、ファイルをまたいで一つの原子にまとまる（§2 の規則どおり）。T1 では、3 地域の「需要の変動にさらされない職である」が `f2` 一つになる。仕様どおりの挙動だが、生成されたファイルでは意図しない共有になりやすい。生成側で地域名を文言に含めるか、mext.py に「事実をファイルごとに区別する」オプションを設けることが考えられる（§6.4）。
- **`verify --skeptical` と `*` のない予測**: `*` のない予測は、`--skeptical` の下では「すべての Extension」で検査される。「preferred でない Extension がある」という予測（P2）は、必ず NG になる。仕様どおりの挙動だが、レポートを読む人が誤解しないよう、出力に「preferred でない Extension についての予測なので懐疑的には成り立たない」などの注記があるとよい。
- **既存の [extensions]**: 既存の `.mext` を渡されたとき、生成部分にすでに Extension が書かれていると、手順4の「solve 前の予測」が盲検にならない。スキルの手順2で、既存ファイルの生成部分を `init` 相当の状態に戻す（Extension を消す）オプションがあるとよい。
