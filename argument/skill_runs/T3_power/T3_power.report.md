# Extension レポート: T3_power（wage_core.matcha + wage_periphery.matcha + power_periphery.matcha）

対象は `T3_power.mext` で、`theory:` は 3 行ある（既存の MEXT なので `init` は省いた）。3 ファイルとも `argument/build_argument.py` が `sims/out/*.json` から生成したものである。この理論の主題は次の一点にある。

> 周辺では「補償賃金差の原則」と「身分秩序（民法92条の事実たる慣習）」が衝突する。その衝突を解く優先順位は法の内部からではなく、力関係（Sim 3 の o_F が閾値を超えること）から与えられる。

## 1. 構文チェック

（matcha_check.py の出力）


エラー・警告はない。木構造の要点:

- `wage_core` と `wage_periphery` は同じ形の 3 主張からなる。
  - 補償原則（`>> not 非正規の賃金は正規より低くてよい`）
  - 身分秩序（当為の層）
  - 身分秩序の実態（存在の層）
- 中核の身分秩序の 2 主張には `!` が、周辺の 2 主張には `+` が付いている。
- `power_periphery.matcha` は `:: 優先 $身分秩序_周辺 > $補償原則_周辺` の 1 行だけで、ファイルをまたいでラベルを参照している。

## 2. AI の判断（[ai] / [extra]）

### same / neg / failure / effect

**どれも書いていない。** 理由は次のとおり。

- 不一致の手がかりになる、別の主張で根拠なしに繰り返された要件はない（3 主張とも自前の根拠を持つ）。
- `>> not` は変換で `-c` になっている（`補償原則_*` の結論は `-c1` / `-c4`）。
- 結論の型について:
  - `!` の付いた中核の 2 主張は「不成立からの帰結」と読まれている。
    - c2「中核では身分秩序による賃金の切り下げは認められない」
    - c3「中核では非正規の賃金が実際に低いとはいえない」
    - どちらも文言上、不成立からの帰結そのものなので、既定の読みは正しい。
  - `+` の周辺の 2 主張は「効果」と読まれ、これも正しい。

### [extra]

本体には何も足していない。足さなくても論証は形式的に成り立ち、著者の根拠は結論につながっている。

### 保留した判断

- **c2 と c1（中核）を `neg` とするか**: 保留した。
  - c2「身分秩序による切り下げは認められない」は「身分秩序という根拠では c1 が出ない」という意味である。
  - c1「非正規の賃金は正規より低くてよい」そのものの否定ではない。別の根拠で c1 が立つ余地を残している。
  - 中核では補償原則がすでに ¬c1 を出しているので、同一視しても結論は変わらない。
- **「慣習が成立している」（当為の層）と「慣行が続いている」（存在の層）を `same` とするか**: しない。
  - 同じ事実（割合 0.978 / 0）から出ているが、著者は層を意図して分けている（コミット bc7f890 の Sein/Sollen の区別）。
  - 統合すると、存在から当為への移行が見えなくなる。

## 6. あてはめの実質的妥当性

review の表は §2 にある。以下は、構造上の問題と事実の扱いについての指摘である（いずれも AI の判断）。

1. **「受け入れる」から「慣習による意思」への飛躍（v7, doubtful）**
   - Sim 3 の事実は、身分賃金 0.629 が正規職の列に並ぶ価値 0.563 を上回る、ということだけである。
   - これは外部機会が乏しいために、身分賃金を受けるほうが「まし」だということで、慣習に従って契約する意思とは同じではない。
   - 民法92条の「意思」の推認は、この区別を問わずに行われがちである。批判的に見れば、ここが力関係を合意に見せかける接合点である。
   - 試算 `T3_power.alt-coerced.mext`（§8）では、この点を争って立証が成れば、周辺の結論が逆転することを示した。
   - 中核の v3 も同じ型の翻訳だが、§4 で見たとおり、中核の結論は v2 だけでも支えられる。
2. **92条の適用範囲の限定が要件にない**
   - 民法92条は「法令中の公の秩序に関しない規定と異なる慣習」についての規定であり、任意規定の領域に限られる。
   - wage_periphery.matcha のコメントは「任意法の領域で」と前提しているが、Matcha の要件には現れていない。
   - 均等・均衡待遇（パートタイム・有期雇用労働法 8・9 条）のような強行的な規律が及ぶなら、そもそも k5 は立たない。
   - この論点は T4（law_periphery_*）の主題なので、T3 では [extra] に足さなかった。T3 の結論は「92 条の領域であれば」という条件付きで読むべきである。
3. **補償原則の規範性（存在から当為への移行）**
   - Smith／Rosen の補償賃金差は、本来、均衡賃金についての**記述的な予測**である（不安定な職には割増が付く）。
   - この理論ではそれを「低くてよいとはいえない」という**当為**の主張として使っている。法の内部で何がこの規範を支えるのか（均衡待遇の理念か、公序か）は、明示されていない。
   - 記述的な予測として読むなら、周辺の存在の層の観測 c5「非正規の賃金は実際に正規より低い」は、補償原則の**反証**である。
   - しかし変換では c4（当為）と c5（存在）は別の原子なので、この緊張は Extension に現れない。著者が意図した層の分離が、ここでは補償原則の反証を見えなくする方向にも働いている。
4. **優先順位の出所**
   - `:: 優先 $身分秩序_周辺 > $補償原則_周辺` には、法的な根拠（特別法・上位法・後法）が書かれていない。
   - power_periphery.matcha のコメントが言うとおり、根拠は「論理の外（力関係）」である。
   - 形式的には一つの優先順位にすぎないが、実質的には**法的な正当化ではなく、事実としての支配の記録**として読むべきである。
   - 試算 `alt-nopower` と `alt-reverse` が示すように、周辺の当為の結論は、この一行に全面的に依存している。
5. **数値の扱い**
   - 事実の文言に閾値の比較が埋め込まれている（「0.629 は 0.563 を上回る」など）。そのため、数値が変わると原子の文言そのものが変わる。
   - 事実どうしの食い違いはない。power_periphery のコメントの o_F = 0.08（timeseries）と、wage_periphery の「o_F ≈ 0.08」（sweep）も整合している。

reject はないので、書かれたとおりの理論（asis）は本体と**同一**である（`T3_power.asis.mext` は作っていない）。

**試算**（いずれも `T3_power.alt-*.mext`。本体の判断ではない）

## 10. 結論

**(a) 形式的妥当性**: 成り立つ。

- 周辺の「非正規の賃金は正規より低くてよい」は、唯一の preferred Extension E2 に含まれ、懐疑的帰結である。
- 中核の「低くてよいとはいえない」「身分秩序による切り下げは認められない」「実際に低いとはいえない」も懐疑的帰結である。
- 著者の印は、preferred Extension ですべて一致する。Lean で E1・E2 が Extension であることを確認した。
- ただし周辺の当為の結論は、`power_periphery.matcha` の優先順位 1 行に全面的に依存している。これを外すと、信憑的帰結にとどまる（alt-nopower）。

**(b) 実質的妥当性**: 条件付きであり、争いうる。

- 中核の結論は堅い。慣行が 0 であるだけで身分秩序は落ちる。
- 周辺の結論は、次の 3 点に支えられている。
  1. 外部機会の乏しさからの受諾を「慣習による意思」と読むあてはめ（doubtful。§6 の 1）
  2. 92 条が働く任意法の領域であるという、明示されていない前提（§6 の 2）
  3. 法的根拠のない、力による優先順位（§6 の 4）
- とくに 1 は、争って立証が成れば、優先順位とは無関係に結論が逆転する（alt-coerced）。
- 論証としてまとめると、T3 は「周辺の非正規の低賃金は法的に正当化される」ことを示すのではない。示しているのは、**法的推論の形をとった正当化が、要件の段階（強いられた受諾を意思と読むこと）と優先順位の段階（力）の二か所で、論理の外の支配関係に依存している**ことであり、そう読むのが妥当である。これはウォーラーステインの言う、周辺における非経済的強制を伴う労働統制の、法的言語による写しと言える。

## 道具について

- 不具合は見当たらなかった。
- 気づいた点が一つある。alt-coerced では `[extra]` の `priority 強制 > e7` で、自動生成の評価デフォルト名 `e7` を指している。§3 の書式は「原子は文言で指す」としているが、priority はデフォルト名でしか指せない。そのため、`e7` のような自動名は、Matcha ファイルの評価の行が増減すると変わりうる（試算ファイルを再生成するときに注意）。
