## 6. あてはめの実質的妥当性

### (1) 周辺の第3要件の対象のずれ（reject の理由）

`+%正規が通常でなくなっている <= 周辺の職の0.513が非正規である@正規は通常ではない`

- 主張の対象は「周辺の**安定した**職」である。ところが 0.513 は、**変動する職を含む全体**の非正規の割合である（`sim2.json handoff.periphery.high.nonregular_share`）。
- sim2 のモデル（`sims/sim2_labor_market.py` の冒頭: 「変動する職は非正規」）では、変動する職の割合は撤退ハザード h_F が小さいときの非正規の割合 0.305 にあたる。この職は常に非正規である。
- σ が h_F によって変わらないと仮定すると、安定した職の中の非正規の割合は次のとおりで、**安定した職の約 7 割はまだ正規**である。

  (0.513 − 0.305) / (1 − 0.305) ≈ **0.30**
- 同じデータから「（安定した職で）正規は通常ではない」は出てこない。これは事実と評価が対応しない場合にあたるので、reject とした。

この reject で結論が変わる（§4）。

- **書かれたとおり**: 周辺では例外が勝ち、¬「期間の定めのない雇用が通常である」となる。
- **審査を反映**: 周辺でも原則が働く。

### (2) 第3要件が結論とほぼ同じことを言っている（構造の問題）

例外の結論は「¬期間の定めのない雇用が通常である」で、第3要件「正規が通常でなくなっている」とほぼ同じ内容である。そのため、例外の論証は半ば**結論を前提に置いて**いる。

本来、ウォーラーステイン的な論証で言いたいのは、次の二つの位置から非正規化が**生じる**ということのはずである。

- 世界システム上の位置（周辺）
- 外資の退出オプション

第3要件は、その帰結の観測にすぎない。

### (3) 閾値 0.09 の出どころ（中核の doubtful）

閾値 h_F = 0.09 は、**周辺の**曲線で非正規の割合が基準を超え始める点である。中核自身の曲線（`sim2.json mobility.core`）では、非正規の割合は h_F ≈ 0.23 まで 0.305 のままである。

- この閾値を中核に当てはめても、h_F = 0.05 は下回るので、結論の向きは変わらない。
- ただし、評価「退出の脅しは雇用形態を左右しない」から言えるのは「退出の脅しが**効かない**」ことである。要件「退出オプションが**ある**」の否定（存在の否定）までは言えない。

なお、中核の例外は v1 だけでも不成立になる（AND の根拠 1/2）。v2 が争われても結論は揺るがない。

### (4) 原則の根拠の射程

`#雇用安定の原則^中核の雇用慣行（労働契約法18条・労働者派遣法25条の趣旨を反映）` は、周辺と地域U にもそのまま適用されている。

- これは「中核の慣行を世界大の原則（デフォルト）とし、周辺はその例外として扱う」という著者の設計で、ファイルの見出しも「事実上の規範秩序として」となっている。
- 実定法としての日本法を周辺に適用しているわけではない、と読むべきである。
- 加えて、労働契約法18条（無期転換）の要件は「通算 5 年」であって、「業務の恒常性」ではない。r1 等のあてはめを ok としたのは、両条の**趣旨**（恒常的な業務は無期・直接雇用が原則）として読んだからである。

### (5) 数値の照合（事実の食い違い）

sims/out の値と照合した。食い違いはない。

- sim1 ring10["0.6"] の工業能力のシェア: 地域4 = 9.737 / 10.00 = 0.974、地域0 = 0.0347 / 10.00 = 0.0035
- sim2 handoff の値: hF_periphery = 0.25、hF_core = 0.05、periphery.high.nonregular_share = 0.5134
- 周辺の均衡は、`start` が high でも low でも同じ値になった。初期値には依存しない。

## 8. 反論の候補（立証責任）

- **周辺**（本体 → 例外へ）

  - **試算 alt-stable-share** では、この事実と評価を `[extra]` に足した（mext.py の出力）。
    ```
    Extension 2 個（preferred 1 個）
    S1: OK（すべてのpreferred Extensionで成り立つ: E2）
    ```
    → 例外が立つ。ただし、事実は sim2 の既定の撤退ハザード 0.25 ではなく 0.35 のものなので、**シミュレーションの前提を変えた試算**である。
  - もう一つの道は、第3要件そのものを外すことである（alt-two-reqs）。例外の要件の設計を変えることになるので、著者の判断を要する。
- **周辺**（書かれたとおり → 原則へ）
  - 原則側は、e5 の評価を争えばよい（§6 (1)）。
  - e3・e4（位置・撤退ハザード）を争う余地は小さい。
- **中核**
  - 例外側が勝つには、e1（シェア 0.974 → 周辺ではない）を覆す必要がある。数値の上では無理である。
  - e2 は doubtful だが、それだけでは足りない。
- **地域U**
  - 例外の立証責任は例外側にある。r9・r10 に事実が書かれていないので、原則が働いている。
  - 地域U が周辺に位置し、撤退ハザードが閾値を超えることを事実で示せば、周辺と同じ構図に移る。そのときも、第3要件のない 2 要件の AND なので、(1)(2) の問題は生じない。

## 10. 結論

### (a) 形式的妥当性

- **書かれたとおりの理論**: 著者の印は、preferred Extension E2 にすべて含まれ、整合している。
  - 中核: 例外不成立、原則が働く

  - 地域U: 例外の立証なし、原則が働く

### (b) 実質的妥当性

### 道具について

- **`explain` の不正確な表示**: review で reject された評価（v5）について、「これを導く規則・デフォルトがない（あてはめる事実が書かれていない）」と表示された。事実 f9 は W にあり、実際の理由は「評価デフォルト e5 が AI の審査で棄却された」ことである。`report` の末尾には正しく注記されている（「e5 は AI の審査で棄却された」）。`explain` でも、棄却を理由として示すのが望ましい。
- **空の `cli_stdout.txt`**: このディレクトリにある `cli_stdout.txt`（0 バイト、未追跡）は、以前の CLI 実行の残りとみられる。このスキルの実行では使っていない。
